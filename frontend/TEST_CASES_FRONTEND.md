## 1. 测试范围与策略

### 1.1 范围内

- 认证与登录态：登录、注册、退出、刷新恢复、过期/失效。
- 路由与鉴权边界：受保护路由的直达、站内跳转、前进后退、404。
- 首页 AI 检索：正常、异常、超长输入、竞态、URL 状态。
- 竞赛列表与筛选：级别、科目多选、空态、错误态。
- 竞赛详情：字段兼容、Markdown 攻略、外链。
- 我的备赛与备赛工作台：列表、加入/移出、三个 Tab、切赛事隔离。
- AI 计划：生成、反问、增量修改、重新生成、缓存恢复。
- 本地存储：配额、脏数据、隐私模式、多标签页、账号隔离。
- 主题：三套主题切换、暗黑（科技蓝）全组件对比度。
- 可访问性、响应式、浏览器兼容、图片与性能、基础安全。

### 1.2 范围外

- 后端接口实现正确性、AI 生成内容质量、数据库数据准确性。
- 压力测试与容量规划（仅做前端侧性能基线）。
- 原生 App / 小程序。

### 1.3 测试层级建议

| 层级 | 工具建议 | 覆盖重点 |
| --- | --- | --- |
| 纯函数单测 | Vitest | `competitionMapper`、`competitionCategory`、`planCache`、`formatSavedAt`、`toMonth` |
| 组件测试 | Vitest + Vue Test Utils + MSW | `CompetitionCard`、`AuthModal`、`Toast`、空/错/载三态 |
| E2E | Playwright | 登录、检索、加入备赛、生成计划、退出、切赛事 |
| 可访问性 | axe-core + Lighthouse | 对比度、焦点、语义、aria |
| 性能 | Lighthouse CI + WebPageTest | LCP/CLS/INP、图片与包体预算 |

## 18. 端到端主流程剧本

### 剧本 A：新用户完整备赛（P0 冒烟）

1. 首次访问首页 → 默认 official 主题，热门竞赛 ≤ 8 条。
2. AI 检索“数学建模” → 进入结果 → 点第一张卡片进详情。
3. 点“加入备赛”（未登录）→ 弹登录 → 注册新账号。
4. 登录成功后回到详情/备赛流程（当前需手动再点，见 FR-05）。
5. 加入备赛 → 进入 `/preparation` → 看到该竞赛。
6. 进入工作台 → 生成计划 → 刷新 → 计划恢复。
7. 切到“获奖作品” → 打开作品 → AI 解析成功。
8. 切到“灵感工作台” → 收藏 1 条 → 刷新 → 收藏仍在。
9. 切到另一赛事 → 计划/作品/灵感均为新赛事内容。
10. 退出登录 → 受保护路由不可进。

### 剧本 B：异常恢复（P0）

1. 断网状态下打开首页 → 错误态 + 重试。
2. 恢复网络 → 重试成功。
3. 生成计划时切走再切回 → 不串台、不永久 loading。
4. 手动清空 localStorage 后刷新 → 页面正常回初始态。

### 剧本 C：主题与可访问性（P1）

1. 三主题逐一走完首页/列表/详情/工作台/个人中心。
2. axe 扫描 0 个 serious/critical。
3. 键盘完成登录与生成计划。
4. 200% 缩放无内容丢失。

### 剧本 D：多账号隔离（P0）

1. U1 登录，生成计划 A、收藏 2 条。
2. 退出，U2 登录，进入同一竞赛。
3. U2 看不到 U1 的计划与收藏。

### 剧本 E：慢网竞态（P1）

1. Slow 3G 下打开工作台 A。
2. 立即返回并进入 B。
3. A 的详情/作品/灵感/计划响应陆续返回。
4. 页面始终只显示 B 的数据。
